4. Asymmetric embedding contracts for `intfloat/multilingual-e5-small`.
5. ChromaDB storage conventions, sequential replacement, and deterministic indexing.
6. Semantic retrieval contracts with MMR diversification and threshold filtering.
7. Benchmark evaluation methodology and quantitative metrics.

## 2. Core Schemas & Data Contracts

All schemas are formalized in Python dataclasses in `src/knowledge_base/schemas.py`.

### 2.1 `DocumentChunk`
Represents an atomic, word-aware text segment extracted from enterprise nutritional documents, regulatory standards, or zero-waste recipe SOPs.

```python
@dataclass(frozen=True)
class DocumentChunk:
    chunk_id: str
    text: str
    metadata: dict[str, str | int | float | bool]
```

#### Fields:
* `chunk_id` (`str`): Unique, deterministic identifier. Format: `{source_id}_p{page_start:03d}_c{chunk_index:04d}`.
* `text` (`str`): Cleaned, normalized chunk text. Must not be empty. Must not exceed 512 tokens after prefixing.
* `metadata` (`dict[str, str | int | float | bool]`): Flat dictionary containing **only** ChromaDB-compatible primitive scalars (`str`, `int`, `float`, `bool`).

#### Metadata Specification:
| Key | Type | Requirement | Description |
| :--- | :--- | :--- | :--- |
| `source_id` | `str` | **Required** | Unique identifier of parent document (e.g., `SOP-WASTE-2026-001`). |
| `chunk_index` | `int` | **Required** | 0-indexed sequential position of the chunk in the document. |
| `source_title` | `str` | Optional | Human-readable title of the document. |
| `issuer` | `str` | Optional | Publishing authority (e.g., "Kemenkes RI", "Instalasi Gizi NutriNexa"). |
| `year` | `int` | Optional | Publication / revision year (e.g., 2026). |
| `document_type` | `str` | Optional | Type: `sop`, `pedoman_gizi`, `resep_zero_waste`, `pdf`, `text`. |
| `category` | `str` | Optional | Category (e.g., `waste_mitigation`, `clinical_nutrition`). |
| `language` | `str` | Optional | ISO language code (default: `id`). |
| `page_start` | `int` | Optional | Starting page number in source document. |
| `page_end` | `int` | Optional | Ending page number in source document. |
| `section_title` | `str` | Optional | Header / heading under which chunk appears. |
| `source_path` | `str` | Optional | Relative path to source file (e.g., `data/knowledge_base/sop.md`). |
| `source_url` | `str` | Optional | URL if sourced from external registry. |
| `file_hash` | `str` | Optional | SHA-256 checksum of raw source file for cache invalidation. |
| `pipeline_version` | `str` | Optional | Version of ingestion pipeline (e.g., `v1.0.0`). |

> [!WARNING]
> ChromaDB rejects nested dictionaries, lists, or `None` values in metadata. Any optional fields with `None` values must be omitted or sanitized before database submission.

### 2.2 `EmbeddingResult`
Represents the vector output produced by `EmbeddingEngine`.

```python
@dataclass(frozen=True)
class EmbeddingResult:
    text: str
    embedding: list[float]
    token_count: int
    model_name: str
```

#### Fields:
* `text` (`str`): The original text string.
* `embedding` (`list[float]`): Dense L2-normalized float vector of length 384.
* `token_count` (`int`): Exact number of tokens generated by the model's tokenizer (including special tokens and prefix).
* `model_name` (`str`): Model identifier (`intfloat/multilingual-e5-small`).

---

### 2.3 `RetrievalResult`
Represents an enriched search result returned by `SemanticRetriever`.

```python
@dataclass(frozen=True)
class RetrievalResult:
    chunk_id: str
    text: str
    metadata: dict[str, str | int | float | bool]
    rank: int
    distance: float
    similarity: float
```

#### Fields:
* `chunk_id` (`str`): Identifier of the retrieved chunk.
* `text` (`str`): Document chunk text content.
* `metadata` (`dict`): Scalar metadata payload.
* `rank` (`int`): 1-indexed retrieval ranking order ($1 \le rank \le k$).
* `distance` (`float`): Cosine distance computed by ChromaDB ($0.0 \le distance \le 2.0$).
* `similarity` (`float`): Cosine similarity score, calculated strictly as:
  $$\text{similarity} = 1.0 - \text{distance}$$

## 3. Document Ingestion & Preprocessing Contract

Implemented in `src/knowledge_base/preprocessing.py` and `src/knowledge_base/document_loader.py`.

### 3.1 Preprocessing (`preprocessing.py`)
* `clean_text(text: str) -> str`: Normalizes line endings (`\r\n` -> `\n`), standardizes typography quotes/dashes, eliminates internal redundant whitespaces while preserving markdown headers (`#`, `##`) and lists (`*`, `-`), and collapses consecutive blank lines to standard paragraph breaks (`\n\n`).
* `is_valid_document_text(text: str, min_chars: int = 20) -> bool`: Filters empty documents, noise, or scanned PDFs lacking OCR text layer.
* `extract_frontmatter(raw_text: str) -> tuple[dict, str]`: Extracts YAML frontmatter keys and returns sanitized body text.

### 3.2 Document Loader (`document_loader.py`)
* Supported extensions: `.md`, `.txt`, `.pdf` (using `pypdf.PdfReader`).
* Calculates real SHA-256 `file_hash` for document provenance and cache invalidation.
* Preserves page numbers (`page_start`, `page_end`) across multi-page documents.
* Merges metadata from `data/knowledge_base/manifest.json` and document frontmatter.

## 4. Word-Aware Chunker Contract (`chunker.py`)

Implemented in `src/knowledge_base/chunker.py`.

### 4.1 Recursive Boundary Splitting
1. **Paragraphs:** Split text by double newlines (`\n\n`).
2. **Sentences:** If a paragraph exceeds `chunk_size` or token limit, split by sentence punctuation (`(?<=[.!?])\s+`).
3. **Words:** If a sentence exceeds `chunk_size`, split by word boundaries (` `).

### 4.2 Sliding Window Overlap & Empirically Selected Configuration
Berdasarkan hasil eksperimen perbandingan komparatif terhadap 16 dokumen korpus dan 30 kueri evaluasi (`scripts/experiment_chunking.py`), **Config A** terbukti menghasilkan granularitas semantik dan skor temu-balik tertinggi:
* **Optimal Chunk Size:** 150 kata (~218 token).
* **Optimal Overlap:** 30 kata (~45 token).
* **Token Distribution:** Min 82, Mean 218.1, P95 309.3, Max 326 token (jauh di bawah batas 512 token).
* **Sentence Boundary Preservation:** 94.0%.
* **Strict Token Ceiling:** Evaluated via `EmbeddingEngine.count_tokens()`. Tidak ada satupun chunk yang melebihi batas 512 token.

## 5. Embedding Engine Contract (`multilingual-e5-small`)

Implemented in `src/knowledge_base/embedding_engine.py`.

* **Model:** `intfloat/multilingual-e5-small`
* **Dimension:** $D = 384$
* **Max Token Limit:** $T_{\max} = 512$ tokens
* **Device:** Explicitly `cpu`
* **Normalization:** L2-normalized (`normalize_embeddings=True`)
* **Asymmetric Prefixing:**
  - Documents / Chunks: `passage: <text>`
  - Search Queries: `query: <text>`
  - Double-prefixing prevention enforced.

## 7. Semantic Retriever Contract (`retriever.py`)

Implemented in `src/knowledge_base/retriever.py`.

* Query prefixing with `query: ` via `EmbeddingEngine.embed_query()`.
* **Cosine Similarity Ranking:** Sorted by highest similarity ($\text{similarity} = 1.0 - \text{distance}$).
* **Metadata Filtering:** Optional ChromaDB `where` filters.
* **Out-of-Distribution Thresholding:** Optional `min_similarity` parameter to filter irrelevant queries.
* **Maximal Marginal Relevance (MMR):** Optional diversification re-ranking:
  $$\text{MMR} = \arg\max_{d_i \in R \setminus S} \left[ \lambda \cdot \text{Sim}(d_i, q) - (1 - \lambda) \cdot \max_{d_j \in S} \text{Sim}(d_i, d_j) \right]$$

## 8. Benchmark Evaluation Suite & Metrics

Implemented in `scripts/benchmark_retrieval.py` with queries in `data/evaluation/benchmark_queries.json`.

* **Hit@K ($K \in \{1, 3, 5\}$):** Percentage of in-domain queries where a ground-truth relevant document is retrieved in top-$K$.
* **Mean Reciprocal Rank (MRR):**
  $$\text{MRR} = \frac{1}{|Q|} \sum_{i=1}^{|Q|} \frac{1}{\text{rank}_i}$$
* **Latency Profile:** Measures mean, min, max, and P95 retrieval latency per query on CPU.
* **Baseline Benchmark Results (T03 Final Evaluated Ingestion):**

  - **Hit@3 (Macro):** 100.0%
  - **Hit@5 (Macro):** 100.0%
  - **Document Recall@1 (Macro):** 79.7%
  - **Document Recall@1 (Micro):** 72.4% (21/29 instance ground truth pada top-1)
  - **Document Recall@5 (Macro):** 100.0% ($\le 1.0$)
  - **Document Recall@5 (Micro):** 100.0% (29/29 instance ground truth pada top-5)
  - **Chunk Precision@5 (Macro):** 54.8%
  - **Document Precision@5 (Macro):** 25.2%
  - **Mean Reciprocal Rank (MRR):** 0.9493
  - **Kerangka Keputusan Tiga Arah OOD (Three-Way Decision):**

## 2. Core Schemas & Data Contracts

All schemas are formalized in Python dataclasses in `src/knowledge_base/schemas.py`.

### 2.1 `DocumentChunk`
Represents an atomic, word-aware text segment extracted from enterprise nutritional documents, regulatory standards, or zero-waste recipe SOPs.

```python
@dataclass(frozen=True)
class DocumentChunk:
    chunk_id: str
    text: str
    metadata: dict[str, str | int | float | bool]
```

#### Fields:
* `chunk_id` (`str`): Unique, deterministic identifier. Format: `{source_id}_chunk_{chunk_index:04d}` (or SHA-256 hash).
* `text` (`str`): Cleaned, normalized chunk text. Must not be empty. Must not exceed 512 tokens after prefixing.
* `metadata` (`dict[str, str | int | float | bool]`): Flat dictionary containing **only** ChromaDB-compatible primitive scalars (`str`, `int`, `float`, `bool`).

#### Metadata Specification:
| Key | Type | Requirement | Description |
| :--- | :--- | :--- | :--- |
| `source_id` | `str` | **Required** | Unique identifier of parent document (e.g., `SOP-GIZI-2026-001`). |
| `chunk_index` | `int` | **Required** | 0-indexed sequential position of the chunk in the document. |
| `source_title` | `str` | Optional | Human-readable title of the document. |
| `issuer` | `str` | Optional | Publishing authority (e.g., "Kemenkes RI", "Instalasi Gizi Del"). |
| `year` | `int` | Optional | Publication / revision year (e.g., 2026). |
| `document_type` | `str` | Optional | Type: `sop`, `pedoman_gizi`, `resep_zero_waste`, `regulasi`. |
| `category` | `str` | Optional | Food category or topic (e.g., `protein_nabati`, `penyimpanan_dingin`). |
| `language` | `str` | Optional | ISO language code (default: `id`). |
| `page_start` | `int` | Optional | Starting page number in source document. |
| `page_end` | `int` | Optional | Ending page number in source document. |
| `section_title` | `str` | Optional | Header / heading under which chunk appears. |
| `source_path` | `str` | Optional | Relative path to source file (e.g., `data/sop/sop_gizi.md`). |
| `source_url` | `str` | Optional | URL if sourced from external registry. |
| `file_hash` | `str` | Optional | SHA-256 checksum of raw source file for cache invalidation. |
| `pipeline_version` | `str` | Optional | Version of ingestion pipeline (e.g., `v1.0.0`). |

> [!WARNING]
> ChromaDB rejects nested dictionaries, lists, or `None` values in metadata. Any optional fields with `None` values must be omitted or sanitized before database submission.

### 2.2 `EmbeddingResult`
Represents the vector output produced by `EmbeddingEngine`.

```python
@dataclass(frozen=True)
class EmbeddingResult:
    text: str
    embedding: list[float]
    token_count: int
    model_name: str
```

#### Fields:
* `text` (`str`): The original text string.
* `embedding` (`list[float]`): Dense L2-normalized float vector of length 384.
* `token_count` (`int`): Exact number of tokens generated by the model's tokenizer (including special tokens and prefix).
* `model_name` (`str`): Model identifier (e.g., `intfloat/multilingual-e5-small`).

---

### 2.3 `RetrievalResult`
Represents an enriched search result returned by `SemanticRetriever`.

```python
@dataclass(frozen=True)
class RetrievalResult:
    chunk_id: str
    text: str
    metadata: dict[str, str | int | float | bool]
    rank: int
    distance: float
    similarity: float
```

#### Fields:
* `chunk_id` (`str`): Identifier of the retrieved chunk.
* `text` (`str`): Document chunk text content.
* `metadata` (`dict`): Scalar metadata payload.
* `rank` (`int`): 1-indexed retrieval ranking order ($1 \le rank \le k$).
* `distance` (`float`): Cosine distance computed by ChromaDB ($0.0 \le distance \le 2.0$).
* `similarity` (`float`): Cosine similarity score, calculated strictly as:
  $$\text{similarity} = 1.0 - \text{distance}$$
  *(Do not apply arbitrary Out-Of-Distribution thresholds at this layer).*

## 3. Embedding Engine Contract (`multilingual-e5-small`)

### 3.1 Model Specification
* **HuggingFace Hub ID:** `intfloat/multilingual-e5-small`
* **Embedding Dimension:** $D = 384$
* **Max Sequence Length:** $T_{\max} = 512$ tokens (including `[CLS]`, `[SEP]`, and prefix)
* **Normalization:** L2-normalized (`normalize_embeddings=True`, $\|\mathbf{v}\|_2 = 1.0$)
* **Default Device:** `cpu` (explicitly configured; no automatic CUDA selection)
* **Default Batch Size:** $B = 8$

### 3.2 Asymmetric Prefixing Contract
The E5 family requires task-specific prefixes:
* **Passage / Document Ingestion:** Must be prefixed with `passage: `
* **Query / Search Retrieval:** Must be prefixed with `query: `

#### Idempotency Rule:
The embedding engine must verify text prefixes:
```python
if is_query:
    prefixed = text if text.startswith("query: ") else f"query: {text}"
else:
    prefixed = text if text.startswith("passage: ") else f"passage: {text}"
```
Double-prefixing (e.g., `passage: passage: ...`) is strictly forbidden.

### 3.3 Token Limit Enforcement & Validation
* Before encoding, `EmbeddingEngine.count_tokens(text, is_query)` must be evaluated.
* If `token_count > 512`, the engine **MUST NOT silently truncate**. It must raise a `ValueError` indicating the exact token count and violation, requiring the upstream chunker to resize the chunk.

## 4. Vector Store Contract (`ChromaDB`)

### 4.1 Persistence & Location
* Client type: `chromadb.PersistentClient`
* Storage Path: `storage/chroma_db/` (git-ignored, configurable)
* Collection Name: `nutrinexa_knowledge_base`
* Space Metric: Explicitly configured as `{"hnsw:space": "cosine"}`

### 4.2 Idempotent Operations
* **Insertion:** Use `collection.upsert(...)` with deterministic IDs. Re-running ingestion must update existing records without generating duplicate entries.
* **Batching:** Vector store operations must support batching (default batch size: 100) to prevent memory spikes on 8 GB RAM machines.
* **Source-level Replacement:** 
  ```python
  vector_store.delete_by_source(source_id: str)
  vector_store.replace_source_documents(source_id: str, chunks: list[DocumentChunk], embeddings: list[list[float]])
  ```
  Ensures that when a document is revised, old chunks are cleanly removed prior to inserting new chunks.
